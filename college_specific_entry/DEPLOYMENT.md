# Deploying AINT for your college

AINT is deployed **one instance per college**. Each college runs its own server,
database and domain, so student data never leaves the college's control.

## What a college needs

- A server or VM (Node 20+, Python 3 if using TTS)
- A database (see `schema.sql`)
- A domain with HTTPS, e.g. `exams.yourcollege.edu`
- At least one AI provider key (Gemini, Groq or OpenRouter)

## Setup

1. Copy `.env.example` to `.env` and fill in every value.
2. Create the database and run `schema.sql`.
3. `npm install`, then `npm start`.
4. Build the browser extension for your domain:
   `npm run build:extension`, then zip `dist/extension` and distribute it.
5. Visit `PUBLIC_URL` and confirm the health check at `/` lists your AI providers.

## Rules for contributors

- Read settings from `config.js` only. Never use `process.env` directly elsewhere.
- Never hardcode `localhost`, a domain, a college name or a database host.
- Frontend code reads `window.AINT_CONFIG` (served from `/config.js`).
- The extension reads `self.AINT_CONFIG` (generated by the build script).
- Only put non-secret values in `publicConfig()`.

## Before sharing the repo with another college

Remove or git-ignore: `.env`, `aint_backup.sql`, `server.backup.js`, `output.txt`,
`audio_cache/`, built `.zip` files, and `.venv/`. Backups can contain real student data.
Keep one canonical `schema.sql` and delete the old schema copies.
